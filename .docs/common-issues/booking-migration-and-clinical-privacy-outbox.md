# Booking Migration: Clinical Privacy Wall, Slot Locks, Direct Google Sheets/Gmail Outbox & Test Normalization

## Symptoms & Risks
1. **Clinical Intake Leakage across Admin Roles**: Storing sensitive psychological complaints (complaints, crisis/self-harm screening flags, detailed intake notes) on the main `bookings` table or exposing clinical intake records on `/api/admin/bookings` and CSV exports violates the Clinical Privacy Wall.
2. **Double-Booking Race Conditions & Missing Session Buffers**: Concurrent public booking submissions or admin status promotions into `confirmed`/`in_session` without database serialization or inter-session buffer windows risk double-booking a psychologist at overlapping times.
3. **Synchronous Webhook Coupling & Column-Index Brittleness**: Calling external webhooks inline during a DB transaction causes lost bookings on downtime, while hardcoding fixed sheet column offsets breaks whenever non-IT editors reorder or insert columns in Google Sheets.
4. **Google Sheets API `values.append` Table Detection Gotcha When `A1` Is Blank**: On sheets where column `A` holds a row-number formula (`=ROW()-1`) with `A1 == ""` and labels starting at `B1` (`Name`), calling `values/'Sheet1'!A1:append?insertDataOption=INSERT_ROWS` fails to detect the table anchored at `B1` and inserts a brand-new row at Row 1 — pushing headers down to Row 2 (`=ROW()-1` evaluates to `"0"`).
5. **Vitest `@/lib/api` Global Mock & Legacy URL Rewriting**:
   - `apps/web/tests/setup.ts` globally mocks `../src/lib/api`, causing feature modules built on `@/lib/api` to fail component integration tests that stub `globalThis.fetch`.
   - Prefix-stripping legacy URLs (`booking.attentiveid.com/...`) without exact-root guards rewrites subpaths like `/enterprise` to `/booking` incorrectly.

## Root Fixes
- **Strict Table Split with Operational Parity (Clinical Privacy Wall)**: Keep scheduling/billing/status metadata in `bookings` (with future registered-client hooks `clientUserId`, `emailNormalized`, `whatsappE164`) and isolate clinical intake records inside `booking_clinical_intakes` so `/api/admin/bookings*` and CSV exports never query clinical intakes, while dispatching Column `J` (`Concern Note`) and operational notification emails as required by operations.
- **Advisory Lock + 15-Minute Buffer Overlap Check**: Wrap slot reservations and `confirmed`/`in_session` transitions in PostgreSQL transactions guarded by `pg_advisory_xact_lock` keyed per psychologist/date and reject conflicting slots (including a 15-minute buffer) with HTTP `409`.
- **Durable PostgreSQL Outbox + Header-Aware Google Sheets & Gmail REST API (`booking_webhook_deliveries`)**: Enqueue outbox events transactionally with idempotency keys, retry backoff, and manual admin retry. Deliver directly via Google Sheets REST API v4 + Gmail REST API using Row 1 (`A1:AZ1`) header alignment (auto-appending `W:AC` headers such as `Booking Code`, `Base Rate`, `Assessment Fee`, `Total Rate`, `UTM Source`, `UTM Medium`, `UTM Campaign` when missing), and pass the full table span `'Sheet1'!A1:<lastCol>1:append` so Sheets detects the header row even when `A1` is blank.
- **Native `fetch()` in Feature Services & Exact-Root Legacy Normalizers**: Use native `fetch()` in `apps/web/src/features/booking/service.ts` (aligned with `apps/web/tests/setup.ts`) and match only exact root `^https?:\/\/booking\.attentiveid\.com\/?$` when normalizing legacy CTA links so `/enterprise` and subpath URLs stay intact.
