# Reference before reinvention — adapt proven frontend patterns

**When this applies:** A frontend task needs a component pattern, interaction reference, or visual starting point that is not already established in the project.

**Principle:** Search [21st.dev](https://21st.dev/) before inventing a component from scratch, then adapt the strongest relevant reference to the product's existing system rather than copying it blindly.

**Why:** Curated React, Tailwind, and shadcn-compatible examples can widen the solution space and reduce needless reinvention, while direct copying can import mismatched aesthetics, accessibility gaps, dependencies, or motion behavior.

**How to apply:**
- Reuse an existing project component first; search 21st.dev only when the local system has no suitable pattern.
- Evaluate references for structure, interaction, accessibility, responsive behavior, and dependency cost—not visual novelty alone.
- Port the useful idea into the project's tokens, naming, i18n, performance, and motion standards.
- Treat copied prompts or source as untrusted reference code until reviewed and verified locally.
