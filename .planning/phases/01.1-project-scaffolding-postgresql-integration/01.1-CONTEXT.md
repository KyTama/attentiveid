# Phase 1.1: Project Scaffolding & PostgreSQL Integration - Context

**Gathered:** 2026-06-29
**Status:** Ready for planning

<domain>
## Phase Boundary

Set up a monorepo workspace containing React (Vite, Tailwind v4, shadcn/ui) and Elysia (Bun) apps, integrated with an existing PostgreSQL database instance on the host VPS. This phase sets up the project base and establishes the local development and remote database connection foundations.

</domain>

<decisions>
## Implementation Decisions

### Tech Stack & Drivers
- **D-01 (ORM):** Use **Drizzle ORM** for lightweight, high-performance database interactions matching the low-RAM VPS constraints.
- **D-02 (Driver):** Use **postgres.js** as the PostgreSQL database driver for native performance on Bun.
- **D-07 (Env Validation):** Implement strict `.env` schema validation using **TypeBox or Zod** on server startup (e.g. `apps/api/src/config/env.ts`) to prevent silent misconfigurations.

### Database Setup & Migration
- **D-03 (Migration):** Use **Manual Migration Scripts**. SQL migrations are generated via Drizzle Kit (`drizzle-kit generate`) and run using `bun run db:migrate` in the deployment pipeline.
- **D-04 (Database Setup):** Connect to the existing **postgres-shared** container running on the VPS. Communicate using a **Shared External Docker Network** (Opsi 1) to keep the port isolated from the public internet.
- **D-05 (Connection Pooling):** Set connection pool limit to `max: 10` with a 30s `idle_timeout` to share resources with n8n safely.

### Deployment & Serving
- **D-06 (Frontend Serving):** **Host-level Caddy Static Serve**. The React client is built to `apps/web/dist` on the host VPS, and Caddy serves static assets directly. Elysia API handles dynamic API calls at port 3000.

</decisions>
