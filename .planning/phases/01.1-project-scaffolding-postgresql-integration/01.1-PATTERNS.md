# Phase 1.1: Project Scaffolding & PostgreSQL Integration - Patterns

This document maps the planned changes to the codebase structure, establishing the data flow, roles, and concrete code patterns required for Phase 1.1 based on CONTEXT and RESEARCH.

## 1. Monorepo Configuration

### `package.json` (Root)
- **Role:** Monorepo Workspace Root & Script Orchestration
- **Data Flow:** Executes global commands bridging frontend and backend workspaces.
- **Closest Analog:** Existing `package.json`
- **Pattern Excerpt:**
  ```json
  "workspaces": [
      "apps/*",
      "packages/*"
  ],
  "scripts": {
      "db:generate": "cd apps/api && bun run db:generate",
      "db:migrate": "cd apps/api && bun run db:migrate"
  }
  ```

## 2. API Infrastructure & Database Setup

### `apps/api/package.json`
- **Role:** Backend dependency management
- **Data Flow:** Resolves packages required for the API and Database interactions.
- **Closest Analog:** Existing `apps/api/package.json`
- **Pattern Excerpt:**
  ```json
  "dependencies": {
      "drizzle-orm": "^0.30.0",
      "postgres": "^3.4.4",
      "@sinclair/typebox": "^0.32.0"
  },
  "devDependencies": {
      "drizzle-kit": "^0.20.14"
  }
  ```

### `apps/api/src/config/env.ts`
- **Role:** Environment Variable Validation (Decision D-07)
- **Data Flow:** First step in server startup. Fails fast if required variables (like `DATABASE_URL`) are missing.
- **Closest Analog:** N/A (New Configuration Pattern)
- **Pattern Excerpt:**
  ```typescript
  import { t } from 'elysia';
  import { Value } from '@sinclair/typebox/value';

  const EnvSchema = t.Object({
      DATABASE_URL: t.String(),
      PORT: t.Optional(t.String()),
      FRONTEND_URL: t.Optional(t.String())
  });

  export const env = Value.Cast(EnvSchema, process.env);
  const errors = [...Value.Errors(EnvSchema, process.env)];
  
  if (errors.length > 0) {
      console.error("❌ Invalid environment variables:", errors);
      process.exit(1);
  }
  ```

### `apps/api/src/db/index.ts`
- **Role:** Database Connection Initialization (Decision D-01, D-02)
- **Data Flow:** Establishes connection pool and returns Drizzle ORM instance to be used across the application.
- **Closest Analog:** N/A (New Infrastructure)
- **Pattern Excerpt:**
  ```typescript
  import { drizzle } from 'drizzle-orm/postgres-js';
  import postgres from 'postgres';
  import { env } from '../config/env';

  // D-05: max 10 connections, 30s idle timeout
  const queryClient = postgres(env.DATABASE_URL, {
      max: 10,
      idle_timeout: 30
  });

  export const db = drizzle(queryClient);
  ```

### `apps/api/drizzle.config.ts`
- **Role:** Drizzle Kit Configuration (Decision D-03)
- **Data Flow:** Dictates how `drizzle-kit` reads schemas and outputs SQL migration files.
- **Closest Analog:** N/A
- **Pattern Excerpt:**
  ```typescript
  import { defineConfig } from 'drizzle-kit';

  export default defineConfig({
      schema: './src/db/schema.ts',
      out: './drizzle',
      dialect: 'postgresql',
      dbCredentials: {
          url: process.env.DATABASE_URL!
      }
  });
  ```

## 3. Docker & Deployment Networking

### `docker-compose.yml` (Root)
- **Role:** Container Orchestration & Network Linking (Decision D-04)
- **Data Flow:** Connects the local API container to the `postgres-shared` database instance residing on the host's existing Docker network.
- **Closest Analog:** N/A
- **Pattern Excerpt:**
  ```yaml
  services:
    api:
      build: 
        context: .
        dockerfile: apps/api/Dockerfile
      ports:
        - "3000:3000"
      networks:
        - default
      env_file:
        - .env

  networks:
    default:
      name: n8n-network
      external: true
  ```

### `.env.example`
- **Role:** Documentation
- **Data Flow:** Provides a reference configuration template.
- **Closest Analog:** N/A
- **Pattern Excerpt:**
  ```env
  # PostgreSQL Connection to shared instance
  DATABASE_URL=postgresql://user:password@postgres-shared:5432/attentiveid
  
  # API Port
  PORT=3000
  
  # Frontend Proxy URL
  FRONTEND_URL=http://localhost:5173
  ```
