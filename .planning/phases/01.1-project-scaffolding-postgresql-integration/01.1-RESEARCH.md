# Phase 1.1: Project Scaffolding & PostgreSQL Integration - Research

## Overview
To effectively plan Phase 1.1, we need to understand the structural requirements of the monorepo, the precise configurations for the tech stack (Bun, Elysia, React, Vite, Tailwind v4, Drizzle ORM, postgres.js), and the Docker networking setup required to connect to the existing shared PostgreSQL database on the host VPS.

## Key Technical Requirements
1. **Monorepo Setup:**
   - Root `package.json` with workspace configuration for `apps/web` (React) and `apps/api` (Elysia).
   - Unified script runners for development and database migrations.
2. **Backend (Bun/Elysia) Setup:**
   - Scaffold Elysia API (`apps/api/src/index.ts`) running on port 3000.
   - Implement strict environment variable validation using TypeBox or Zod (e.g., `apps/api/src/config/env.ts`) to prevent silent misconfigurations (Decision D-07).
   - Configure Drizzle ORM with the `postgres.js` driver.
   - Database connection pooling set to `max: 10` with a 30s `idle_timeout` to ensure stable resource sharing with n8n (Decision D-05).
   - Set up `drizzle-kit generate` and `bun run db:migrate` scripts (Decision D-03).
3. **Frontend (React/Vite/Tailwind) Setup:**
   - Scaffold React + Vite app in `apps/web`.
   - Configure Tailwind CSS v4 and shadcn/ui.
   - Ensure Vite proxies `/api` requests to `localhost:3000` during development.
4. **Docker & Network Integration:**
   - Create a `docker-compose.yml` for the `api` container.
   - Link to the existing external Docker network (`n8n-network`) to access the `postgres-shared` container.
   - Connection string format: `postgresql://<user>:<password>@postgres-shared:5432/attentiveid`.

## Validation Architecture
According to the Nyquist validation strategy, we must define explicit verification criteria for each component before considering the phase complete.

### 1. Monorepo & Backend Validation
- **Test:** Run `bun install` from the root and verify workspaces are linked successfully.
- **Test:** Run `bun run dev` and verify the Elysia server starts successfully on `localhost:3000`.
- **Test:** Intentionally remove a required environment variable (e.g., `DATABASE_URL`) and verify the server crashes on startup with a schema validation error (TypeBox/Zod).

### 2. Frontend Validation
- **Test:** Run the Vite development server and successfully access `localhost:5173`.
- **Test:** Verify Tailwind v4 classes are applying correctly to a dummy component.
- **Test:** Execute an API call from the React frontend to the `/api` endpoint and verify the Vite proxy forwards it correctly to Elysia without CORS issues.

### 3. Database & Network Validation
- **Test:** Execute `bun run db:migrate` and verify tables are successfully created in the `postgres-shared` database.
- **Test:** Ensure the API container successfully connects to the `postgres-shared` database using the `n8n-network` Docker network.
- **Test:** Validate the connection pool limits by inspecting the PostgreSQL active connections (should not exceed 10 from the API).

## Implementation Risks & Considerations
- **VPS RAM Constraints:** Keep dependencies minimal and ensure the Docker setup for the API relies solely on Bun without heavy layers.
- **Shared Network Access:** The `api` container must explicitly declare `external: true` for the `n8n-network` in its Docker Compose file; otherwise, it won't resolve `postgres-shared`.
- **Caddy Production Parity:** While development will use Vite's proxy, production relies on Caddy proxying `/api/*`. Keep API route structures consistent.
