# Phase 1.2: Vex Page Sections Porting & Tailwind v4 Customization - Context

**Gathered:** 2026-06-29
**Status:** Ready for planning

<domain>
## Phase Boundary

Building the landing page layout by porting existing "Vex" template sections into React + Tailwind v4 components, prioritizing modern frontend standards and premium UX over pixel-perfect legacy markup.

</domain>

<decisions>
## Implementation Decisions

### Component Strategy & Structure
- **D-01:** Adapt to shadcn/ui primitives wherever possible to ensure accessibility (a11y) and maintain UI consistency, rather than porting raw HTML from the Vex template.
- **D-02:** All new landing page section components will be organized inside `apps/web/src/components/landing`.

### UI/UX & Motion
- **D-03:** Use **Framer Motion** for animations and scroll transitions to provide a premium, natural UX (spring physics, layout transitions) suitable for a psychological bureau.
- **D-04:** Stick strictly to Tailwind's default responsive breakpoints to ensure alignment with shadcn/ui and simplify maintenance, ignoring custom Figma breakpoints if they conflict.

### Content Strategy
- **D-05:** Set up i18n keys and translations immediately during the porting process using `react-i18next`, avoiding hardcoded text.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `apps/web/src/lib/utils.ts`: Contains the `cn` utility wrapper for clsx and tailwind-merge; mandatory for merging Tailwind classes dynamically.
- `apps/web/src/hooks/useInView.ts`: Available hook for intersection observation (though Framer Motion's `whileInView` may supersede this for complex animations).

### Established Patterns
- Strict TypeScript (`~5.9.3`) is enforced.
- Tailwind CSS v4 is used with utility classes applied directly in JSX.
- Internationalization (i18n) uses `useTranslation` hook; strings are not hardcoded.

### Integration Points
- `apps/web/src/pages/LandingPage.tsx`: The primary container that will compose the new section components from `components/landing`.
