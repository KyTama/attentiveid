# Phase 1.2: Vex Page Sections Porting & Tailwind v4 Customization - Research

## Context and Goal
This phase aims to re-create the landing page layout by porting existing "Vex" template sections into modern React components styled with Tailwind v4. The priority is establishing a premium user experience with modern frontend standards, suitable for a psychological bureau, over pixel-perfect legacy markup.

## Core Requirements (REQ-04, REQ-06)
- **Design Tokens & Layout:** Adhere to Figma design for tokens, layout, and branding (REQ-04).
- **Styling & Frameworks:** Utilize Tailwind CSS v4 and `shadcn/ui` for consistent and accessible styling (REQ-06).
- **Responsiveness:** Maintain a mobile-first approach.

## Implementation Strategy
1. **Component Organization:** All landing page section components will be created under `apps/web/src/components/landing`.
2. **UI Component Primitives:** Favor `shadcn/ui` primitives whenever possible instead of raw HTML ports from the Vex template to ensure robust accessibility (a11y) and visual consistency (Decision D-01).
3. **Animations and Motion:** Implement `framer-motion` for scroll transitions and animations. Use natural spring physics to convey trust, calmness, and a high-quality impression (Decision D-03).
4. **Responsive Design:** Strictly adhere to Tailwind's default breakpoints to ensure compatibility with `shadcn/ui` and ease of maintenance, overriding any conflicting Figma breakpoints (Decision D-04).
5. **Internationalization (i18n):** Avoid hardcoding text. Utilize `react-i18next` and the `useTranslation` hook to set up i18n keys immediately during the porting process (Decision D-05).

## Existing Code Context
- **Utility Functions:** Use the `cn` utility located in `apps/web/src/lib/utils.ts` for dynamic Tailwind class merging.
- **Assembly:** The individual landing page section components will be composed within the primary container at `apps/web/src/pages/LandingPage.tsx`.

## Technical Considerations (Based on Project Skills)
- **React Patterns:** Ensure strict TypeScript typing (`~5.9.3`).
- **Tailwind v4 Patterns:** Leverage Tailwind v4 CSS-first configuration and utility classes directly in JSX.
- **Frontend Design / UI UX Pro Max:** Ensure the final product matches a high-quality, premium aesthetic with subtle micro-interactions suitable for psychological services.

## Validation Architecture
To verify the successful completion of this phase, the following validation steps must be executed:

1. **Visual & Responsive Validation:**
   - Verify the landing page components render correctly across mobile (`sm`), tablet (`md`), and desktop (`lg`, `xl`) viewports using Tailwind's default breakpoints.
   - Confirm layout matches the structural intent of the Figma designs and standard `shadcn/ui` patterns.

2. **Styling & Motion Validation:**
   - Ensure all styling uses Tailwind v4 utility classes (no legacy CSS).
   - Verify that `framer-motion` is used for enter/scroll animations and behaves naturally (spring physics) without performance jank.

3. **Internationalization (i18n) Validation:**
   - Audit the newly created components in `apps/web/src/components/landing` to ensure no hardcoded English/Indonesian strings exist.
   - Verify that `useTranslation` and appropriate translation keys are implemented for all text nodes.

4. **Code Quality & Accessibility Validation:**
   - Run type-checking to ensure TypeScript compliance.
   - Use browser DevTools (or `ux_audit.py` if applicable) to ensure ARIA labels and semantic HTML from `shadcn/ui` primitives are intact and accessible.
