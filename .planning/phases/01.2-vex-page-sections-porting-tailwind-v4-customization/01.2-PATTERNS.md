## 2. Landing Page Section Components

### File(s)
- `apps/web/src/components/landing/*.tsx` (Created/Modified - e.g., `Hero.tsx`, `AboutUs.tsx`, etc.)

### Role & Data Flow
- **Role:** Presentation components for distinct sections of the landing page (e.g., Hero, About, Services).
- **Data Flow:** Presentation-only or consumes local data/i18n. Will utilize `react-i18next` (`useTranslation`) for content to avoid hardcoded text, and `framer-motion` for entrance/scroll animations with natural spring physics.

### Closest Analog
- `apps/web/src/components/landing/Hero.tsx`

### Code Excerpt & Expected Refactoring Pattern
*Note: Existing sections need to be refactored to incorporate Framer Motion and i18next.*

```tsx
// Pattern for typical section
import { useTranslation } from 'react-i18next'
import { motion } from 'framer-motion'
import { cn } from '@/lib/utils'

export function Hero() {
    const { t } = useTranslation()

    return (
        <section
            id="hero"
            className="relative h-screen w-full flex items-center justify-center overflow-hidden"
        >
            {/* Background Image / Overlay logic here */}

                    viewport={{ once: true }}

                    {t('landing.hero.tagline')}
                </motion.p>
```

## 3. Tailwind Class Merging Utility

### File(s)
- `apps/web/src/lib/utils.ts` (Reference, unmodified)

### Role & Data Flow
- **Role:** Utility for merging Tailwind CSS classes dynamically while handling precedence and conditional logic.
- **Data Flow:** Consumes varying arrays or strings of classes and outputs a safe, conflict-free string.

### Closest Analog
- N/A - it is a utility function.

### Code Excerpt
```typescript
import { type ClassValue, clsx } from "clsx"
import { twMerge } from "tailwind-merge"

export function cn(...inputs: ClassValue[]) {
    return twMerge(clsx(inputs))
}
```
