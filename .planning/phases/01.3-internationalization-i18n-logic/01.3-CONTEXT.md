<domain>
## Phase Boundary

Setting up complete multi-language support (English & Bahasa Indonesia) for the landing page. This includes mounting the full `LandingPage` component as the app root, aligning JSX translation keys with the translation files, and extracting remaining hardcoded/placeholder strings in the Footer, Services, and Contact sections.

<decisions>
## Implementation Decisions

### Navigation & Routing
- **D-01:** Update `apps/web/src/App.tsx` to render `<LandingPage />` instead of the hardcoded dummy sections. This will make the `Navbar` and `LanguageSwitcher` visible at the root.

### Translation Keys & Catalogs
- **D-02:** Standardize all translation keys in the components to match the flat catalog structure in `en.json` and `id.json` (e.g., using `hero.greeting` instead of the mismatched `landing.hero.hello` or `landing.hero.greeting`). We will use the single unified file approach for all translation keys.

### Services Alignment (Old Content + Figma Styling)
- **D-03:** Align `apps/web/src/components/landing/Services.tsx` with the catalog data:
  - Render the three original clinical therapy categories: **Adult Psychotherapy** (`services.items.adult`), **Child & Adolescent Psychotherapy** (`services.items.child`), and **Family or Couple Therapy** (`services.items.family`).
  - Maintain the Figma design styling (layout grid, custom cards, gold accent tokens, and Lucide icons like `Users`, `Brain`, `Activity`).

### Extracting Hardcoded Text & Info
- **D-04:** Replace remaining hardcoded/placeholder texts with translation keys:
  - Localize "View on Maps" button in `Contact.tsx` to `contact.mapsBtn`.
  - Replace the placeholder contact details in `Footer.tsx` (address, phone) with localized and corrected variables mapped to the i18n dictionaries.
  - Implement i18next interpolation for the copyright text: `{t('footer.copyright', { year: new Date().getFullYear() })}`.

</decisions>
