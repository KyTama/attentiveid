## Discussion Points & Alignments

### 1. App Entry Point (`App.tsx`)
- **Alignment:** Approved **A.1**. `App.tsx` will be modified to mount `<LandingPage />` dynamically, bringing the full page structure (with `Navbar` and the `LanguageSwitcher`) into view.

### 2. Translation File & Key Structure
- **Alignment:** Approved **B.1**. A single unified translation file (`en.json` / `id.json`) will be maintained. We will clean up the prefix `landing.` from components (`Hero`, `Services`, `Footer`) to match the flat structure inside the locale catalogs. For future dashboard sections, separate namespaces or grouped object blocks will be appended to the same file.

### 3. Services Component Mapping
- **Alignment:** We aligned on combining the clinical therapy content of the old Hugo website (Adult Psychotherapy, Child & Adolescent Psychotherapy, and Family or Couple Therapy) with the Figma UI design.
- **Decision:** The cards in `Services.tsx` will retain the visual cards and icon assets designed in Figma, but their titles and description fields will fetch translations from `services.items.adult`, `services.items.child`, and `services.items.family`.

### 4. Info & Hardcoded Strings Extraction
- **Alignment:** Approved **D.1**. The hardcoded Google Maps link string ("View on Maps") will be moved to the dictionaries. The address and phone details in the footer will be fully localized/corrected according to the official contact variables.
