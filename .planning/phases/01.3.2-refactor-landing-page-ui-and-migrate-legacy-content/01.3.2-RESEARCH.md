# Phase 01.3.2: Refactor Landing Page UI and Migrate Legacy Content - Research

**Goal:** Answer "What do I need to know to PLAN this phase well?"

## 1. Scope & Objective
- **Objective:** Completely replace the old landing page layout with the new Tailwind v4 + Figma design.
- **Content:** Preserve existing business content by migrating it from legacy YAML files into `i18n` locale files (`en.json`, `id.json`).
- **Figma Reference:** The planner and implementer MUST refer to the official [Figma Design](https://www.figma.com/design/1nvcVPQadGoCOCn3cC8DCY/Attentive-Landing-Page?node-id=0-1&p=f&t=p7zY0xXhV68lFGb3-0).
- **Conflict Resolution:** If legacy content does not perfectly fit the Figma layout, the **Figma layout wins**. Adapt content to fit the design.

## 2. Component Structure & Hierarchy
The landing page must be broken down into granular components orchestrated by a main `LandingPage.tsx` component. The strict vertical order must be:
1. Hero
2. About Us
3. Why Attentive
4. Psychologists
5. Testimonials
6. Services & Download Catalogue
7. Partner Content
8. CTA Take the First Step
9. Clinics Locations

## 3. Data Migration & i18n Strategy
- **Source of Truth:** All legacy landing page content must be sourced from `/Users/kytama/Projects/Neo-Attentive/attentiveid.github.io/data/en/homepage.yml`.
- **Locale Files:** Extract all strings immediately into `en.json` and `id.json`. No hardcoded strings in JSX.
- **Default Language:** `id` (Bahasa Indonesia) is the default base locale. Populate both `id.json` and `en.json`.
- **Mapping Data:** The planner will need to specify how to map legacy YAML arrays (e.g., psychologists, insights) to the props of the new Figma-based React components.
- **Fallback UI:** If a section has no data in the legacy YAML, display a fallback/placeholder (e.g., "Coming soon") instead of hiding the section.

## 4. Technical Guidelines
- **Styling:** Tailwind CSS v4 utilities directly in JSX. Use the `cn` function (`src/lib/utils.ts`) for merging classes. Use `shadcn/ui` where applicable.
- **Responsiveness & Performance:** Mobile-first design, aiming for a sub-1.5 second load time.
- **Animations:** Implement scroll-driven reveal animations (fade-up/slide-in on scroll) rather than static presentation.
- **Assets:** Migrate all legacy images from the old project into the new Vite `public` folder.
- **i18n Implementation:** Use `react-i18next` hooks (`useTranslation`) for accessing the extracted strings.

## 5. Planning Caveats & Risks
- **Data Mismatches:** If there is a major mismatch between legacy YAML content and required Figma sections that cannot be easily adapted, the planner should flag it for re-discussion instead of making destructive assumptions.
- **Plane Integration:** Any new tasks/plans generated must be synced to the Plane ATTN project as per `GEMINI.md` mandates.
