# Phase 1.3.2 Research: Landing Page UI Refactor & Legacy Content Migration

## 1. UI-SPEC & Design Constraints
Based on `1.3.2-UI-SPEC.md`, the new frontend components must adhere to the following contract:
- **Design System**: shadcn (new-york preset), radix UI components, `lucide-react` icons.
- **Typography**: Inter font. Sizes strictly mapped to Body (16px), Label (14px), Heading (24px), Display (48px).
- **Colors**: 
  - Background (60%): `#FFFFFF`
  - Secondary/Cards (30%): `#F8FAFC`
  - Accent/Primary Buttons (10%): `#2563EB`
- **Focal Point**: The "Take the First Step" CTA button must use the Accent color.
- **Copywriting rules**: Fallback states must read "Coming soon" and "We are currently preparing this section. Check back later!".

## 2. Legacy Data Mapping Strategy
The legacy source of truth is `/Users/kytama/Projects/Neo-Attentive/attentiveid.github.io/data/en/homepage.yml`.
This file must be translated into a structural React hierarchy of 9 sections, populated via `id.json` and `en.json`:

1. **Hero**: Mapped from `banner` and parts of `features` (tagline, titles).
2. **About Us**: Mapped from `features.content1` and `features.content2`.
3. **Why Attentive**: Mapped from `promo` (e.g. "How can we help?" + items).
4. **Psychologists**: Mapped from `psychologists.items`. Need to ensure we correctly map SIPP, locations, specializations, and links.
5. **Testimonials**: Mapped from `testimonial`.
6. **Services & Download Catalogue**: Mapped from `products` and potentially `subscription`.
7. **Partner Content**: Mapped from `insights` (e.g., Muzz blog posts).
8. **CTA Take the First Step**: Brand new visual section prioritizing the CTA.
9. **Clinics Locations**: Mapped from `contact_us.locations` (Jakarta & BSD) and contact details (WhatsApp).

## 3. i18n & Assets Migration Plan
- **i18n Translation Setup**: Since `id.json` is the default locale, the english content from the legacy `homepage.yml` needs to be mapped to both `en.json` (as-is) and `id.json` (translated or structurally placed so that translation happens next).
- **Asset Migration**: The YAML references image paths like `images/hero.webp` and `images/psychologists/Syazka.webp`. These files must be copied from the legacy repo's asset folder to the new project's `public/images/` directory to ensure they resolve correctly in Vite/Next.

## 4. Implementation Steps for Planning (/gsd-plan-phase)
When breaking down this phase into tasks, ensure the following order:
1. **Scaffold Locale Files**: Extract the YAML data into `src/locales/en.json` and `src/locales/id.json`.
2. **Asset Porting**: Script or task to copy the legacy image folder.
3. **Component Generation**: Create 9 distinct section components (e.g., `HeroSection.tsx`, `AboutUsSection.tsx`, etc.) under `src/components/landing/`.
4. **UI Integration**: Build `LandingPage.tsx` strictly stacking the 9 components vertically, applying scroll-driven reveal animations.
5. **Shadcn Integrations**: Verify or install required shadcn components (`Button`, `Card`, `Avatar`).
